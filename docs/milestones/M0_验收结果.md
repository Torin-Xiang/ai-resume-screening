## 交付内容

1. **运行环境**：项目内 `.venv`（Python 3.13.14，托管版创建），`requirements.txt` 与 `pyproject.toml`
   锁定技术栈（PyMuPDF / pydantic v2 / typer / openpyxl / pandas / openai / python-dotenv / tenacity / pytest），
   与方案 §7 完全一致。
2. **分层目录**：`resume_screening/cli`（薄壳）、`core`（纯逻辑）、`adapters/{parsers,llm,exporters}`（三类适配器）。
3. **评分卡 schema**（`core/rubric.py`）：`schema_version` + 业务 `version` + 三类维度
   （`hard_filters` / `bonus` / `red_flags`），每个维度强制 `definition` + `positive_examples` + `negative_examples`（§4.6）。
4. **标识**（`core/ids.py`）：`resume_id` = 文件内容 sha256 前 16 位；`run_id` = 时间戳 + 随机后缀（§6.2）。
5. **合规红线**（`core/compliance.py`）：敏感属性词表 + 拦截入口 + 写入所有 prompt 的合规条款（§4.5）。
6. **LLM 统一入口**（`core/llm.py`）：`LLMClient` 协议 + `MeteredLLM` 计量包装（§6.3）。

## 设计决策（需 HR/业务知晓）

- **合规检查放在维度构造层**（`DimensionBase` 的 model_validator），而不是只在评分卡加载时。
  原因：评分卡有"LLM 生成"和"HR 手改 JSON"两条入口，放在最底层才能两条路径都拦住，
  且被拦时能指出是哪一个维度的哪一个字段。
- **英文敏感词按词边界匹配**：早期版本把 `Agent` 里的 `age` 判成"年龄"维度，已修正并加回归用例
  （`test_agent_keyword_not_false_positive`）。
