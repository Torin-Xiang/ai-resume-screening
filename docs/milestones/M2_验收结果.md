## 交付内容

1. `core/extractor.py`：9 项核心字段（姓名、联系方式、学历、学校、专业、工作年限、现公司、现岗位、技能）
   + 可选扩展字段（现居城市、工作经历、教育经历），每项带 `Evidence`（quote + 页码）与 `status`。
2. `core/evidence.py`：**证据反编造校验**——模型给的 quote 必须在原文中逐字命中（去空白/标点后子串匹配），
   否则该字段降级为 `unparsable` 且 value 置空，并把违规记入 `extras.evidence_violations`。
3. `core/cache.py`：`resume_id` 为键的 JSON 缓存；反序列化失败视为未命中（安全降级重跑）。
4. 规则兜底：联系方式用正则抽取（方案 §4.2 能用规则就不用模型）。
5. 扫描件：不调用模型，直接产出待人工处理的文档（§9）。

## 设计决策

- **"必须带原文引用"由代码强制，不靠 prompt 自觉**：prompt 只是第一道防线，
  真正的保证是 `core/evidence.py` 的命中校验——编造内容在结构上不可能变成"已提取"字段。
- **字段状态三态**（extracted / not_mentioned / unparsable）：`not_mentioned` 供下游标"待确认"，
  绝不当作"不满足"（§4.3）；`unparsable` 表示"有内容但无法可靠结构化"，同样转人工。

## 阻塞项

1. **无真实脱敏简历样本** → 无法统计"字段准确率 ≥ 90%"。
2. **无 `DASHSCOPE_API_KEY`** → 无法跑真实 qwen 抽取；当前用 `FakeLLMClient` 验证链路。
3. 补齐方式：真实样本 + key 到位后，跑 `screen` 导出 Excel，
   用"结论与原文证据"列人工核对 9 字段，统计准确率并回填本文件。
