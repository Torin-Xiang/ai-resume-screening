## 交付内容

1. `core/rules.py`：5 条内置硬门槛规则 —— `min_degree`（学历层次）、`min_years`（工作年限）、
   `location`（现居城市）、`major`（专业关键词）、`job_hop`（平均在职时长/跳槽频次）。
   规则成本 0、准确率 100%、完全可解释（§4.2）。
2. `core/scoring.py`：
   - 硬门槛**优先走规则**；软性维度（含无 rule 的硬门槛、加分项、减分项）走统一 LLM 入口，一次调用批量判定；
   - 判定三态映射：`satisfied / not_satisfied / not_mentioned|unknown`；
   - **证据不命中原文 → 判定作废**（转待确认）；**理由触碰合规红线 → 判定作废**；
   - 计分：`bonus = Σ 权重 × 命中度(0/0.5/1)`，`red_flag` 命中扣分，总分钳制在 `[0, 满分]`；
   - 汇总结论：只有"明确不满足"的硬门槛才一票否决 → `reject`；
     存在未提及/无法判定的硬门槛 → `needs_review`（**绝不淘汰**）；否则 `pass`。

## 设计决策

- **"判定作废"而非"降权"**：模型给出不可追溯的证据或涉红线的理由时，直接把该维度判定为
  `unknown` 并转人工，而不是保留判定、只降可信度。理由：HR 采信的前提是可追溯，
  一个"可能不准"的结论比"没有结论"更危险。
- **软性维度合并为一次 LLM 调用**：口径在同一份上下文里判定，避免多次调用导致口径漂移，
  也降低 token 成本。
